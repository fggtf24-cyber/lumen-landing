# Lumen — развёртывание

Сайт на PHP + MySQL. Сборки и зависимостей нет: залил файлы, создал базу,
заполнил конфиг — работает.

---

## Что здесь есть

| Файл | Зачем |
|---|---|
| `index.php` | сайт; отзывы и кейсы рендерит сервер из БД |
| `send.php` | приём двух форм: заявка → письмо, отзыв → в БД на модерацию |
| `schema.sql` | таблица `reviews`, выполнить один раз |
| `schema-cases.sql` | таблица `cases` + первый кейс, выполнить один раз |
| `config.example.php` | шаблон настроек → скопировать в `config.php` |
| `admin/` | вход, модерация отзывов, управление кейсами |
| `lib/` | `db.php` (PDO), `auth.php` (сессия, CSRF, экранирование), `cases.php`, `Smtp.php` |
| `storage/` | логи и счётчики антиспама, создаётся сам |
| `assets/` | картинки сайта; `assets/cases/` — загруженные снимки кейсов |

**Требования:** PHP 7.4+ с расширениями **mbstring, pdo_mysql, openssl**
(на Beget включены по умолчанию), MySQL 5.7+.

---

## Установка

1. **Файлы** — содержимое репозитория в корень `~/sites/домен.ru/public_html/`,
   вместе со скрытыми (`.htaccess`). Должно получиться:

   ```
   public_html/
     index.php  send.php  schema.sql  config.php  .htaccess
     admin/  lib/  storage/  assets/
   ```

2. **База** — панель Beget → MySQL → создать базу и пользователя.
   Затем phpMyAdmin → вкладка SQL → выполнить содержимое `schema.sql`,
   потом так же `schema-cases.sql`. Оба файла можно выполнять повторно:
   таблицы не пересоздаются, первый кейс не дублируется.

3. **Почта — как на первом кейсе (shorttermtherapy.ru).** Панель Beget → «Почта»
   → создать ящик на своём домене, например `zayavki@ваш-домен.ru`. С него уходят
   письма (`smtp.beget.com:465/ssl`), приходят они на рабочую `lumensites24@bk.ru`.

   Слать «от имени» Gmail/Яндекса/Mail.ru нельзя — чужой SMTP не пропустит ваш
   домен. `user` и `from` в конфиге всегда совпадают.

   Если домена на Beget ещё нет, как временный вариант можно слать с самого
   `lumensites24@bk.ru` через `smtp.mail.ru:465/ssl` — но там в пароль нужен
   «пароль для внешних приложений» (Mail.ru → Настройки → Безопасность).

4. **Конфиг** — скопировать `config.example.php` → `config.php` и заполнить:
   доступы к базе, `admin_password_hash`, SMTP.

   > Отправитель — `zayavkilumen@lumensites.ru` (ящик на своём домене,
   > `smtp.beget.com:465/ssl`), получатель — `lumensites24@bk.ru`.
   > В `config.php` остаётся вписать только пароль от этого ящика.

   Хеш пароля админки:
   ```bash
   php -r "echo password_hash('ваш-пароль', PASSWORD_DEFAULT), PHP_EOL;"
   ```

   > ⚠️ Сохраняйте `config.php` **без BOM** (UTF-8 without BOM). Windows-редакторы
   > любят добавить BOM — тогда байты уйдут раньше HTTP-заголовков и коды ответов
   > сломаются. На это уже наступали при отладке.

5. **Права** — на запись нужны две папки: `chmod 775 storage`
   и `chmod 775 assets/cases` (туда админка кладёт картинки кейсов).

6. **Проверить** — отправить заявку (придёт письмо), отзыв (появится
   в `/admin`) и добавить кейс в `/admin/cases.php`.

## Как это работает

**Заявка** → `send.php` → письмо на `lumensites24@bk.ru`. Если в контакте почта,
она подставляется в `Reply-To` — можно отвечать прямо из письма. В БД не пишется.

**Отзыв** → `send.php` → строка в `reviews` со статусом `pending` + письмо-уведомление.
На сайте **не появляется**, пока не одобрен. Модерация — `/admin`:
«Опубликовать» / «Отклонить» / «Вернуть на модерацию».
`index.php` показывает только `approved`, свежие сверху, максимум 20.

**Кейсы** («Наши работы») лежат в таблице `cases` и целиком управляются из
`/admin/cases.php`: добавить, изменить, скрыть с сайта, переставить местами,
удалить. Порядок на главной задаётся кнопками «Выше»/«Ниже», показываются
только помеченные «Показывать на сайте».

Картинку кейса админка принимает JPEG, PNG или WebP до 6 МБ и пересохраняет
сама: ужимает до 1600 px по ширине, кладёт в `assets/cases/` под случайным
именем и делает рядом webp-версию — карточка отдаёт webp тем, кто его
понимает. Тип определяется по содержимому файла, а не по расширению, поэтому
скрипт, переименованный в `.jpg`, не пройдёт. В самой папке выполнение PHP
запрещено отдельным `.htaccess` — даже если файл каким-то образом туда
попадёт, он не запустится. При удалении кейса его картинки стираются с диска.

Если база недоступна, сайт всё равно открывается: секция отзывов пустая,
а в «Наших работах» показывается первый кейс, вшитый прямо в вёрстку.

## Контракт `send.php`

`POST`, `Content-Type: application/json`.

```json
{ "type": "lead",   "name": "Иван", "contact": "@ivan", "message": "Нужен лендинг…", "company": "" }
{ "type": "review", "name": "Иван", "contact": "@ivan", "text": "Отличная работа…",  "company": "" }
```

| Поле | Правила |
|---|---|
| `type` | `lead` или `review` |
| `name` | обязательно, до 100 символов |
| `contact` | для `lead` обязательно; для `review` необязательно и **не публикуется** |
| `message` | текст задачи (`lead`), до 4000 |
| `text` | текст отзыва (`review`), от 10 до 4000 |
| `company` | honeypot: всегда пустое, у бота заполнено → отвечаем `ok`, ничего не делаем |

Ответы: `200 {"ok":true}` · `422 empty-fields` · `429 too-many-requests` ·
`500 storage-failed` (не записался отзыв) · `500 send-failed` (не ушло письмо) ·
`405 method-not-allowed`.

## Безопасность

- SQL — только подготовленные запросы (PDO, `ATTR_EMULATE_PREPARES = false`).
- Весь вывод в HTML проходит через `e()` (`htmlspecialchars`) — отзывы пишут
  посторонние, это главный барьер против XSS.
- Пароль админки — `password_hash`, в конфиге лежит хеш, не текст.
- Сессия: `httponly`, `samesite=Lax`, `secure` под HTTPS, смена id при входе
  (защита от фиксации сессии).
- CSRF-токен на входе, на всех действиях модерации и на всех действиях с кейсами.
- Перебор пароля: не больше 10 попыток с IP за 15 минут.
- Загрузка картинок: тип определяется по содержимому (`getimagesize`), файл
  пересохраняется через GD — что бы ни было спрятано внутри, до диска оно не
  доедет. Имя файла генерируем сами, из формы не берём. В `assets/cases/`
  своим `.htaccess` запрещено выполнение PHP.
- Формы: honeypot + не больше 5 отправок с IP в час (`rate_limit_per_hour`).
- Из однострочных полей вырезаются переводы строк — иначе через форму можно
  подделать заголовки письма.
- `config.php` и `*.sql` закрыты от веба через `.htaccess`, `config.php` в `.gitignore`.
- Ошибки БД наружу не отдаются: пользователь видит короткое сообщение,
  подробности уходят в лог сервера.

**На проде выключите вывод ошибок:** `display_errors = Off` (панель Beget →
настройки PHP). Иначе при сбое в браузер может попасть путь к файлу.

## Если письмо не пришло

`storage/leads.log` — результат каждой попытки:

| Запись | Что делать |
|---|---|
| `Отправлено.` | письмо ушло — проверьте «Спам» |
| `Ошибка SMTP: … 535 …` | неверный логин/пароль в `config.php` |
| `Ошибка SMTP: Не удалось подключиться` | проверьте `host`/`port` |
| `SMTP не настроен` | в `config.php` остался `ЗАМЕНИТЕ_НА_ПАРОЛЬ` |
| `Не отправлено:` | письмо не ушло; заявка целиком записана здесь же |
| `Не удалось сохранить отзыв:` | проблема с БД, смотрите текст ошибки |

Заявка пишется в лог в любом случае — потерять её из-за сбоя почты нельзя.

## Локальная проверка

```bash
php -S localhost:8080
```

Открыть <http://localhost:8080>, отправить обе формы, зайти в `/admin`.
Нужен `config.php` с доступом к локальной MySQL. Через `python -m http.server`
не заработает — PHP не выполнится.

## Что уже проверено

Полный прогон на локальном PHP 8.3 + MariaDB 11.8 (120 проверок, все зелёные):

**Цикл отзыва — вживую, включая базу.** `schema.sql` выполняется без ошибок;
отзыв с формы уходит в `reviews` со статусом `pending`, кириллица и переводы
строк сохраняются, `ip` и `created_at` заполнены, `moderated_at` пуст; на сайте
такого отзыва нет. В `/admin` — очередь, счётчики, «Опубликовать» →
`approved` + `moderated_at`, отзыв появляется на главной; «Вернуть на
модерацию» и «Отклонить» убирают его обратно. Проверено и через `curl`, и
кликами в браузере. На главной ровно 20 карточек, свежие сверху.

**Безопасность.** Отзыв с `<script>` в имени и тексте выводится экранированным
и на сайте, и в админке. Контакт автора в публичную часть не попадает. Вход:
неверный пароль — отказ, без CSRF — отказ, 10 попыток за 15 минут — блокировка.
Действие модерации без CSRF статус не меняет.

**Формы и сбои.** Коды `send.php`: 405 / 422 / 429 / 500 `send-failed` /
500 `storage-failed`; honeypot отвечает `ok` и ничего не пишет; не больше 5
отправок с IP в час. При выключенном SMTP заявка не теряется — целиком
ложится в `storage/leads.log`, а форма честно говорит «отправить не
получилось». При недоступной базе главная открывается (200) с заглушкой
вместо отзывов, админка пишет человеческое сообщение — ни `SQLSTATE`,
ни путей к файлам наружу.

**Кейсы — вживую, включая загрузку файлов.** `schema-cases.sql` выполняется
и повторный запуск ничего не дублирует. Через админку: добавление с картинкой
(PNG 2400 px пересохранён в JPEG шириной 1600 px, рядом появился webp),
правка без замены картинки старый файл не трогает, «Скрыть»/«Опубликовать»
убирают и возвращают кейс на главную, «Выше»/«Ниже» меняют порядок и на
странице, и в базе, удаление стирает строку вместе с обоими файлами и не
задевает чужие. Ссылка без схемы дополняется до `https://`.

PHP-скрипт с расширением `.jpg` отклонён («Это не изображение»), в базу и на
диск не попал; настоящий PNG с расширением `.txt` принят — тип берётся из
содержимого. Заголовок с `"><script>` выводится экранированным и на главной,
и в админке, и внутри `value` формы правки.

**Почта.** Подключение к `smtp.beget.com:465/ssl` и авторизация ящика из
`config.php` проверены отдельно (соединение + `AUTH LOGIN`, письмо при этом
не отправлялось).

**Осталось проверить на месте:** что письмо реально доходит до
`lumensites24@bk.ru` с боевого хостинга — это зависит уже от Beget, а не от
кода. Отправьте одну заявку после заливки.

Ещё одно нельзя проверить локально: встроенный сервер PHP игнорирует
`.htaccess`, поэтому запрет на выполнение PHP в `assets/cases/` и закрытость
`config.php` подтвердятся только на Apache у Beget. После заливки откройте
`lumensites.ru/config.php` — должна быть ошибка доступа, а не текст файла.
