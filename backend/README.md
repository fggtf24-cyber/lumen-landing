# Lumen — приём заявок и отзывов на почту

Хендофф для бэкенд-разработчика. Здесь всё, чтобы сделать задачу за один заход.

---

## Что нужно сделать

Сайт статический (`../index.html`, без сборки и зависимостей). Динамика одна —
**две формы**, и обе должны приходить **письмом на почту**:

| Форма | Где на сайте | `type` в запросе |
|---|---|---|
| Заявка | секция «Контакты» (`#contact`) | `lead` |
| Отзыв | секция «Отзывы» (`#reviews`) | `review` |

Задача: поднять `send.php` на хостинге и настроить почту. Фронтенд **уже
подключён** — обе формы шлют JSON на `send.php`, ничего править в HTML/JS не нужно.

**База данных не нужна.** Отзывы модерируются вручную (см. ниже).

Делаем так же, как на первом кейсе — [shorttermtherapy.ru](https://shorttermtherapy.ru/),
Beget + SMTP. Код здесь — адаптация того же, проверенного в бою.

## Файлы

```
send.php             приём обеих форм, отправка письма  ← основной файл
config.example.php   шаблон настроек → скопировать в config.php и заполнить
lib/Smtp.php         отправка по SMTP, без зависимостей (взято с первого кейса)
lib/.htaccess        закрывает папку от веба
storage/             лог и счётчик антиспама (создаётся сам)
.htaccess            закрывает config.php от веба
frontend-snippet.js  как форма общается с send.php (справка, менять не нужно)
```

## Развёртывание (Beget)

1. **Куда класть.** Содержимое этой папки — рядом с `index.html`, в корень
   `~/sites/домен.ru/public_html/`. То есть на хостинге должно получиться:

   ```
   public_html/
     index.html          ← сайт
     assets/
     send.php            ← отсюда
     config.php
     lib/Smtp.php
     storage/
     .htaccess
   ```

   Загружать вместе со скрытыми файлами (`.htaccess`) — в FTP-клиенте включите
   их показ.

2. **Почта.** Рабочий ящик — `lumensites24@bk.ru`, письма приходят на него.
   Отправлять письма можно с него же (`bk.ru` — это Mail.ru): нужен **пароль для
   внешних приложений** — Mail.ru → Настройки → Безопасность → «Пароли для
   внешних приложений». Обычный пароль от входа SMTP не пустит.

   Когда появится свой домен на Beget — лучше завести ящик `zayavki@домен.ru`
   (панель → «Почта») и слать с него: для репутации домена это надёжнее.
   Оба варианта расписаны в `config.example.php`.

3. **Заполнить `config.php`** (скопировать из `config.example.php`):

   ```php
   'to' => ['lumensites24@bk.ru'],           // можно несколько

   'smtp' => [
       'host'      => 'smtp.mail.ru',        // для ящика на bk.ru
       'user'      => 'lumensites24@bk.ru',
       'password'  => 'пароль для внешних приложений',
       'from'      => 'lumensites24@bk.ru',  // должен совпадать с user
   ],
   ```

4. **PHP 7.4+** — панель → «Сайты» → настройки сайта.

5. **Права на запись** для `storage/` (обычно уже есть, иначе `chmod 775 storage`).

6. **Проверить**: отправить заявку и отзыв через формы на сайте.

### Если сайт останется на GitHub Pages

Сейчас сайт живёт на <https://fggtf24-cyber.github.io/lumen-landing/>, а там
**PHP не выполняется**. Варианты:

- **Проще всего — перенести сайт на Beget** целиком (как первый кейс). Тогда
  форма и скрипт на одном домене, CORS не нужен, `FORM_ENDPOINT` менять не надо.
- Либо оставить сайт на Pages, а `send.php` положить на Beget. Тогда:
  в `config.php` указать `'allowed_origin' => 'https://fggtf24-cyber.github.io'`,
  а в `../index.html` заменить `var FORM_ENDPOINT = 'send.php'` на полный URL
  скрипта.

## Контракт запроса

`POST send.php`, `Content-Type: application/json`.

```json
{ "type": "lead",   "name": "Иван", "contact": "@ivan", "message": "Нужен лендинг…", "company": "" }
{ "type": "review", "name": "Иван", "contact": "@ivan", "text": "Отличная работа…", "company": "" }
```

| Поле | Правила |
|---|---|
| `type` | `lead` или `review` |
| `name` | обязательно, до 100 символов |
| `contact` | для `lead` обязательно; для `review` необязательно и **в письме помечено «не публикуется»** |
| `message` | текст задачи (`lead`), до 4000 |
| `text` | текст отзыва (`review`), обязателен, от 10 до 4000 |
| `company` | honeypot — всегда пустое; если пришло непустым, это бот: отвечаем `ok`, письмо не шлём |

Ответы: `{"ok":true}` · `422 empty-fields` · `429 too-many-requests` ·
`500 send-failed` · `405 method-not-allowed`.

## Модерация отзывов

Отзыв **никуда не публикуется сам** — он просто приходит письмом с темой
«Отзыв на модерацию». В письме уже лежит готовый блок для вставки. Одобрили —
вставляете его в `../index.html`, в секцию `#reviews`:

```html
<figure class="review">
  <blockquote>Текст отзыва.</blockquote>
  <figcaption>Имя, компания</figcaption>
</figure>
```

Админку и хранилище не делали намеренно: пока отзывов единицы, вставить блок
дешевле, чем поднимать базу с авторизацией. Понадобится автопубликация — это
отдельная задача, текущий контракт под неё не переделывать не придётся.

## Антиспам (уже в коде)

- honeypot-поле `company` — боты заполняют, люди нет;
- не больше 5 отправок с одного IP в час (`rate_limit_per_hour` в `config.php`);
- переводы строк из однострочных полей вырезаются, чтобы через форму нельзя
  было подделать заголовки письма;
- `config.php` с паролем закрыт от веба через `.htaccess` и добавлен в
  `.gitignore` — в репозиторий не коммитить.

## Если письмо не пришло

`storage/leads.log` — там результат каждой попытки:

| Запись | Что делать |
|---|---|
| `Отправлено по SMTP` | письмо ушло — проверьте «Спам» |
| `Ошибка SMTP: … 535 …` | неверный логин/пароль в `config.php` |
| `Ошибка SMTP: Не удалось подключиться` | проверьте `host`/`port`, что ящик создан |
| `SMTP не настроен` | в `config.php` остался `ЗАМЕНИТЕ_НА_ПАРОЛЬ` |
| `НЕ ОТПРАВЛЕНО` | письмо не ушло, но заявка целиком записана здесь же |

Содержимое пишется в лог в любом случае — потерять заявку из-за сбоя почты нельзя.
